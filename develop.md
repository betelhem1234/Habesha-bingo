5. GAME #4 — RISK & STOP
==================================================

Create a fast risk-versus-reward game using virtual points/coins.

The player starts at Level 1.

Example:

LEVEL 1
Reward: 100

[CONTINUE] [COLLECT]

If the user chooses CONTINUE:

LEVEL 2
Reward: 200

[CONTINUE] [COLLECT]

The reward increases as the player continues.

At each level there is a server-generated risk event.

If successful:
advance to the next level.

If unsuccessful:
the uncollected reward is lost.

If the user chooses COLLECT:
the current reward is secured.

Flow:

START
→ Level
→ Continue OR Collect
→ If Continue: server evaluates risk
→ Success: next level
→ Failure: game ends
→ Collect: finish
→ Result

Features:
- Fast rounds
- Increasing rewards
- Risk indicator
- Personal high score
- Daily leaderboard
- Friend challenges
- Streaks
- Difficulty modes

IMPORTANT:
Use virtual points/coins.

Do not assume or implement cash wagering or cash-out.

15. SERVER AUTHORITATIVE GAMEPLAY
==================================================

This is mandatory.

The frontend must NEVER determine:

- winner
- card value
- Kegno numbers
- wheel result
- risk result
- reward
- score
- leaderboard position
- wallet balance

Correct flow:

CLIENT
→ sends action
→ SERVER validates
→ GAME ENGINE processes action
→ DATABASE/STATE updated
→ SERVER sends result
→ CLIENT displays result

Never trust client-generated results.

- move/action sequence number
- player ID
- timestamp

game version 1
game version 2
game version 3

The client sends its expected version.

If the server version differs:

return STATE_OUTDATED

and send the latest state.

Prevent:
- duplicate moves
- double rewards
- race conditions
- concurrent state corruption
